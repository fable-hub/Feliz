`useTransition` lets you update state without blocking the UI. State updates inside `startTransition` are marked as non-urgent: React keeps showing the current UI, renders the new UI in the background and can interrupt that render for more urgent updates such as clicks or typing.

It returns `isPending`, which is `true` while the transition is rendering, and the `startTransition` function.

```fsharp
let isPending, startTransition = React.useTransition ()

Html.button [
    prop.onClick (fun _ -> startTransition (fun () -> setTab "posts"))
    prop.text (if isPending then "Loading..." else "Posts")
]
```

In the example below, rendering the posts tab takes about 300 ms. Click "posts" and then quickly "contact": the buttons stay responsive and the slow render is abandoned.

## Async transitions with `useAsyncTransition`

Since React 19, a transition can be async: `isPending` stays `true` until the returned promise settles. React calls such async transitions "Actions".

The returned `startTransition` function can only have one F# type, so Feliz offers a second hook for async work: `React.useAsyncTransition` is the same React hook, but its `startTransition` takes a `unit -> JS.Promise<unit>`.

```fsharp
let isPending, startTransition = React.useAsyncTransition ()

startTransition (fun () -> promise {
    let! saved = saveName name
    React.startTransition (fun () -> setSavedName saved)
})
```

:::warning

State updates after a `let!` or `do!` are no longer part of the transition. Wrap them in `React.startTransition` again, as shown above. This is a current limitation of React, not of Feliz.

:::

There is no `Async<'T>` overload: React only waits for promises. Convert an F# `async` with `Async.StartAsPromise`.
